## 1. מה נבנה בפרוסה זו

### 1.1 חוזה Page Item + רישום (§6 ו-§10 בהוראה) — `layout/page-items.js`

- **חמשת אופני ההשתתפות** מוכרזים כשדות חוזה (לא מנועים נפרדים): `flow` (פסקה/כותרת/תמונה inline), `block` (תמונת בלוק/פס חוצה-טורים/שער/TOC/עמודי הערות), `anchor` (הערת-צד), `furniture` (כותרת עליונה/גיליון), `reserved` (אזור הערות/עיטור — מזמין שטח לפני הצבת הטקסט).
- **רישום מחמיר** (דפוס model/registry של שלב 2): חריץ זר/השתתפות חסרה/כפילות/reserved-בלי-הזמנה — נדחים בשגיאה מפורשת.
- **11 הסוגים הקיימים רשומים** עם הצהרת סמכות מלאה: השתתפות, אזור, מקור מדידה, סמכות ההחלטה, אבחון, הקרנות DOM/PDF. הבונים הקיימים נשארים הסמכות — הרישום מצהיר ומפרש את המפה; אין מנוע מקבילי.
- **`reservePageItemSpace`**: פריט reserved מזמין מקום דרך `page.reservations` — מנגנון הקיבולת האחיד של שלב 5 (הוכח: footnote-gutter דינמי לפי התקציב; furniture שאינו reserved נדחה).

### 1.2 גיאומטריית ריהוט ממקור יחיד (§8) — `layout/furniture-geometry.js`

- עד כאן הפרויקטור ל-PDF חישב את תיבת הגיליון והבסיס במתמטיקה מפורשת (FOLIO_BOTTOM_PX=25, half-leading, ascent) בעוד ה-DOM הסתמך על CSS חי שכויל להתאים — שני מקורות של אותה גיאומטריה.
- מעתה: `folioGeometry` + `headerGeometry` מחושבים פעם אחת; **הפרויקטור וה-DOM קוראים מאותו מקור**. ה-DOM מציב סגנון מפורש (top/line-height; `bottom:auto`) לצד ה-class שנשאר אחראי לעור (מסגרת/צבע).
- **מוכח בבדיקה:** אותם מספרים בדיוק (y/baselineY/lineHeightPx) בין הפרויקטור לבין הסגנון המפורש ב-DOM — כולל בגופן גיליון רשום (הנתיב שמפעיל מדידה נפרדת). פריסה נייטרלית: hash קנוני `f6f32c40` נשמר ביט-לביט.

### 1.3 חותמות הערות — רוחבי מילים (הכנת §7: "תקציב, הצבה והקרנה מאותם מדדים")

- `stampNoteMetrics` חותמת כעת גם רוחבי-מילים פר-שורה (`row.wordW`) + רוחב סמן + רוחב רווח — ההקרנה (פרוסה 2) תמקם מילים מהחותמת מבלי למדוד שוב. המדידה נותרת אחת (כמוכח ב-s5b-measurement-purity — 7/7 ממשיכים לעבור).

### 1.4 רגרסיה מפורשת — ערכת 40 ועיצובי השערים (§9)

- נעילה כפולה מפורשת: ברירת המקור `active-theme-select=json_theme_40` (אותו קובץ ש-s62 נועל — כאן ברמת סוויטת העימוד) + עימוד ברירת-מחדל עם שם ספר מניב עמודי שער ללא מעורבות משתמש, contentPreserved=true.

## 4. הצעד הבא (פרוסה 2)

(א) מודל הערות המאוחד — צד/שוליים/סיון תחת source/anchor אחד + מקצה אנכי משותף להערות השול + הקרנה מהחותמות (תקציב=הצבה=הקרנה). (ב) פריט מותאם לדוגמה דרך model/registry + page-items — הוכחת parse→validate→resolve→measure→plan→PagePlan→DOM/PDF בלי תנאים מפוזרים. (ג) הגירת המדידות של הערות-הצד למקור אחד.

שער הקבלה המלא: §6.3 בתוכנית.
